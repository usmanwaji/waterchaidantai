# Setup & Usage Guide — thai-docx

Make Thai render correctly in Microsoft Word (`.docx`) files generated by
[python-docx]. This guide walks through install, a one-line quick start, every
public function with an example, the `verify-thai-docx` scanner / CI gate, and a
**pre-delivery checklist** you must run in real Microsoft Word before sending a
document to a client.

---

## 1. Requirements

| Requirement | Notes |
|---|---|
| **Python ≥ 3.9** | Tested on 3.9 – 3.13. |
| **python-docx** (`>=1.0,<2.0`) | Core dependency, installed automatically. |
| **lxml** (`>=4.0`) | Installed automatically (used directly in `fonts.py`). |
| **pythainlp** (`>=4.0`) | **Optional.** Only needed for ZWSP word-break (`insert_thai_breaks`). Features that need it warn and skip if it is absent; everything else still works. |

You do **not** need Microsoft Word installed to *use* the library — but you do
need real Word to *verify* the final document (see [§7](#7-pre-delivery-checklist-open-in-real-word)).

---

## 2. Install

### From PyPI (when published)

```bash
pip install thai-docx              # core
pip install "thai-docx[nlp]"       # + pythainlp (ZWSP word-break)
```

### From source (recommended while developing)

```bash
git clone https://github.com/kkdp13/thai-docx.git
cd thai-docx

pip install -e .                   # core (python-docx + lxml)
pip install -e ".[nlp]"            # + pythainlp for insert_thai_breaks
pip install -e ".[dev]"            # + pytest + pythainlp (run the tests)
```

### Inside a virtualenv (clean, reproducible)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

python -m pytest -q                # 42 tests should pass
```

## 3. Quick start

The 90% case is **one line before `save`**:

```python
from docx import Document
from thai_docx import enforce_thai

doc = Document()
doc.add_paragraph("สวัสดีครับ ราคา 500 บาท")

enforce_thai(doc)                  # fills cs / szCs / bCs / iCs / bidi on every run
doc.save("out.docx")
```

Without `enforce_thai`, Word picks a fallback face for the complex-script slot:
Thai tone marks float (วรรณยุกต์ลอย), the font shrinks, and **bold/italic do not
apply** to Thai. See [`SKILL.md`](../SKILL.md) for the full OOXML explanation.

## 4. Usage — every public function

### `enforce_thai(doc, *, force=False, thai_font=DEFAULT_THAI_FONT, thai_digits=False, insert_breaks=False)`

Fill `w:cs` / `w:szCs` / `w:bCs` / `w:iCs` / `w:lang w:bidi` on **every run**,
plus at the **style** and **docDefaults (`w:rPrDefault`)** levels. Idempotent —
safe to call repeatedly. Call **once before save**.

```python
enforce_thai(doc)                                  # default TH Sarabun New
enforce_thai(doc, thai_font="Sarabun")             # different Thai face
enforce_thai(doc, thai_digits=True)                # also map 0-9 -> ๐-๙
enforce_thai(doc, insert_breaks=True)              # also insert ZWSP (needs pythainlp)
```

### `set_thai_run(run, thai_font, latin_font=None, thai_size=None, latin_size=None, bold=None, italic=None)`

Split font/size between the Thai (`cs`) and Latin (`ascii`/`hAnsi`) slots in a
single run — for mixed Thai + Latin text.

```python
from docx.shared import Pt
from thai_docx import set_thai_run

run = p.add_run("Invoice ใบแจ้งหนี้")
set_thai_run(run, thai_font="TH Sarabun New", latin_font="Calibri",
             thai_size=Pt(16), latin_size=Pt(11), bold=True)
```

### `clean_pdf_thai(text) -> str`

NFC-normalise, strip zero-width / soft-hyphen, reorder swapped tone/vowel marks,
and drop the fake spaces PDFs insert between Thai characters. Keeps English,
numbers and URLs untouched.

```python
from thai_docx import clean_pdf_thai
clean_pdf_thai("ส วั ส ดี​ครับ")     # -> "สวัสดีครับ"
```

### `to_thai_digits(text) -> str`

Map Arabic digits `0-9` to Thai digits `๐-๙`.

```python
from thai_docx import to_thai_digits
to_thai_digits("ราคา 500 บาท")            # -> "ราคา ๕๐๐ บาท"
```

### `insert_thai_breaks(doc)` *(requires `pythainlp`)*

Insert U+200B (zero-width space) at Thai word boundaries so Word wraps lines
sensibly. Skips numbers, English and URLs. Warns and skips if `pythainlp` is not
installed.

```python
from thai_docx import insert_thai_breaks
insert_thai_breaks(doc)
```

### `fix_line_spacing(doc, min_pt=Pt(...))`

Switch the line rule to **"At least"** so tall Thai vowel/tone stacks are not
clipped. Do **not** use Word's "Exactly" rule with Thai.

```python
from docx.shared import Pt
from thai_docx import fix_line_spacing
fix_line_spacing(doc, min_pt=Pt(18))
```

### `apply_thai_gov_layout(doc)`

A4 page, ระเบียบสารบรรณ margins, and TH Sarabun New 16pt on the Normal style.
(The national crest / letterhead block is scaffolded as a TODO — that asset and
document structure are your responsibility.)

```python
from thai_docx import apply_thai_gov_layout
apply_thai_gov_layout(doc)
```

### `fill_template(doc, mapping)`

Replace `{{key}}` placeholders, **preserving the Thai font** of the run holding
the placeholder.

```python
from thai_docx import fill_template
fill_template(doc, {"name": "นายสมชาย", "amount": "5,000"})
```

### `embed_fonts(doc, {family: paths})`

Embed (obfuscated, byte-exact) TrueType fonts so the document renders the same
on machines that do not have the font installed.

```python
from thai_docx import embed_fonts
embed_fonts(doc, {"TH Sarabun New": {"regular": "THSarabunNew.ttf",
                                     "bold":    "THSarabunNew-Bold.ttf"}})
```

> **Font licensing:** only embed fonts whose license permits embedding. *TH
> Sarabun New* (13 ฟอนต์แห่งชาติ, SIPA/DGA) and OFL-licensed fonts are fine.
> Always verify the license of any font you pass in.

### `enforce_thai_file(in_path, out_path, ...)`

Open an existing `.docx`, enforce Thai, and write a copy (atomic write, with an
overwrite guard so you do not clobber a client file by accident).

```python
from thai_docx import enforce_thai_file
enforce_thai_file("client.docx", "client_fixed.docx")
```

## 5. The `verify-thai-docx` scanner

The scanner inspects the **raw OOXML** of every run across all document parts
(body, tables, header/footer, footnotes, endnotes, text boxes, numbering) and
fails if any Thai run lacks `cs` / `szCs` / `bidi`.

```bash
verify-thai-docx fixed.docx            # one file
verify-thai-docx ./out_folder/         # scan a whole folder
```

Exit codes:

| Code | Meaning |
|---|---|
| `0` | All scanned files clean. |
| `1` | At least one Thai run still broken. |
| `2` | Usage error / no `.docx` files found. |

> ⚠️ **Do not trust a LibreOffice or web preview.** LibreOffice applies its own
> Thai shaping and looks fine even when the file is broken for real Word. The
> scanner reads the XML, so it is the source of truth — alongside opening the
> file in actual Microsoft Word.

---

## 6. CI gate

Use the scanner as a gate in CI so a broken Thai document can never ship.
This repo's own workflow runs `pytest` (see
[`.github/workflows/ci.yml`](../.github/workflows/ci.yml)). To gate generated
documents in your own pipeline:

```yaml
- name: Verify generated Thai docx
  run: verify-thai-docx ./build/docs/
```

A non-zero exit fails the job.

## 7. Pre-delivery checklist (open in real Word)

The automated tests assert the XML and reopen the file — they do **not** prove
how Microsoft Word *renders* it. Before sending any document to a client or
filing it officially, **open it in real Microsoft Word** and confirm:

- [ ] **No "recover" prompt.** Word opens the file without the "Word found
      unreadable content / do you want to recover" dialog. (A schema-order bug in
      paragraph properties can trigger this — `fix_line_spacing` was fixed for it,
      but verify after any manual XML edit.)
- [ ] **Footnotes / endnotes** render Thai correctly (no floating tone marks,
      correct font and size).
- [ ] **Embedded font renders on a clean machine.** If you used `embed_fonts`,
      open the file on a computer that does **not** have the Thai font installed
      and confirm it still looks right.
- [ ] **Bold / italic apply to Thai.** Toggle a Thai run bold and confirm it is
      visibly bold in Word (not just in the markup).
- [ ] **Headings do not shrink.** Heading styles keep their intended size — no
      hard `szCs` forced onto runs that inherit their size.
- [ ] **Track-changes survive.** If the source had tracked changes, they are
      still present and correct after processing.
- [ ] **Tone marks not clipped.** Tall Thai stacks (สระ + วรรณยุกต์) are fully
      visible — line spacing is "At least", never "Exactly".

This checklist comes from real delivery experience — see the project's
[`docs/RELEASE-CHECKLIST.md`](./RELEASE-CHECKLIST.md) for the general release
checklist.
